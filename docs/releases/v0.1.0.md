# v0.1.0

Local-first audio transcription, structured summarization, OCR note capture, and semantic recall.

Initial public release of Noterizer: a local-first workflow for transcribing audio, generating structured summaries, indexing notes into ChromaDB, and querying across transcripts, summaries, and image OCR notes.

## Highlights

- Unified `noterizer.py` CLI for audio, image OCR, query, and profile management
- Profile-driven backend configuration for Ollama and OpenAI-compatible APIs
- Audio pipeline now produces transcript JSON + SRT by default
- Structured transcript summarization with `meeting` and `presentation` formats
- Auto-detection of summary format, with explicit override support
- Shared database model across transcript, summary, and OCR note content
- Shared rotating error log at `./noterizer.log`
- Improved handling for long/noisy transcripts, including chunked summarization and trimmed-SRT preference
- Bundled example profiles and updated setup/usage documentation

## Included Tools

- `noterizer.py`
- `run_whisperx.py`
- `summarize_transcript.py`
- `index_transcript.py`
- `ask_memory.py`
- `image_to_note.py`

## Known Limitations

- Summary quality is good but not perfect; human skim review is still recommended for important outputs
- Long or noisy recordings can still require trimming or reruns
- Domain-specific technical vocabulary can still be mis-transcribed and then repeated incorrectly in summaries
- Conference/keynote recordings with uncommon RF or engineering terminology are currently the highest-risk case
- The bundled OpenAI-compatible profile paths are present in code and docs, but `v0.1.0` release validation was performed with Ollama-based profiles only
- Python `3.14` is not currently a supported runtime for the WhisperX dependency stack used by this project; Python `3.12` is the recommended interpreter
- Local model quality and speed depend heavily on your hardware and chosen profile
- Initial setup still assumes some comfort with Python, Ollama, WhisperX, and Hugging Face

## Short GitHub Release Description

`Noterizer v0.1.0` is the first public release of a local-first workflow for audio transcription, structured summarization, OCR note extraction, semantic indexing, and query.

## GitHub Release Notes

What’s included:

- Unified `noterizer.py` CLI for audio, image OCR, query, and profile listing
- Profile-driven backends for Ollama and OpenAI-compatible APIs
- Default transcript outputs: JSON + SRT
- Structured summaries with `meeting` and `presentation` formats
- Auto-detected summary format with explicit override support
- Shared ChromaDB indexing across transcripts, summaries, and image notes
- Shared rotating error log at `./noterizer.log`
- Improved handling for long/noisy transcripts via chunked summarization and trimmed-SRT preference
- Bundled profiles plus updated setup, usage, and profile docs

Known limitations:

- Summary output still benefits from human review
- Long or noisy recordings can still require reruns or trimming
- Domain-specific technical vocabulary can still be mis-transcribed and then misinterpreted during summarization
- Conference/keynote recordings with uncommon RF or engineering terminology are currently the weakest summary case
- OpenAI-compatible profile configurations are included, but this release was only exercised end to end with Ollama-based profiles
- Python `3.14` is not currently supported for the WhisperX stack; use Python `3.12`
- Performance and quality depend on local hardware and model selection
